# Hornbach GM Checklist — working notes

Digital replacement for the four paper checklists used by GM (Godsmottagning) at
Hornbach. The originals are archived in `docs/source-checklists/`; read them
before changing anything about rules, deadlines or wording.

## Non-negotiables

- **Swedish is the source of truth.** Checklist wording comes from the paper
  forms. A translation that shifts a rule's meaning is a safety problem. Add
  keys to `src/lib/i18n/sv.ts` first; `en.ts` is typed against it and will fail
  to compile if a key is missing.
- **One database connection.** `src/lib/db/client.ts` is the only place that may
  construct one. ESLint enforces this — a pool per route handler exhausts the
  Supabase pooler. Do not disable that rule to "just get it working".
- **`/api/*` is never public.** Middleware guards pages; every route handler
  authorizes itself with `requireUser()` / `requireRole()`. Listing `/api` as a
  public path leaves every endpoint open.
- **Type errors fail the build.** `ignoreBuildErrors` stays `false`.
- **Deadlines are resolved in Postgres**, via `AT TIME ZONE 'Europe/Stockholm'`
  — never with JavaScript date arithmetic. DST moves these twice a year.
- **Published template versions are immutable.** A run pins
  `template_version_id`; editing a template must create version N+1. Rewriting a
  published version corrupts history and invalidates signatures.
- **48px minimum touch targets** in the worker shell. Gloves, a 4" screen, a
  cold yard. `Button` defaults to `size="touch"` for this reason; `compact` is
  for the leader's desktop views only.

## Layout

| Path | What lives there |
|---|---|
| `db/schema/` | Drizzle tables, one module per domain, re-exported from `index.ts` |
| `db/migrations/` | Generated by `drizzle-kit`; never hand-edit a committed migration |
| `src/lib/rules/` | The rules engine. `evaluate.ts` must stay a **pure function** — no I/O, no `Date.now()`, `now` is injected. It runs server-side, in the browser and in the service worker; if it reaches for I/O, offline validation drifts from server validation. |
| `src/lib/db/` | Connection singleton and queries |
| `src/lib/i18n/` | `sv` (source of truth) and `en` |
| `seeds/templates/` | Curated, committed template JSON — the source of truth for list content |
| `scripts/` | Dev tooling: the `.xls` importer, seeders, audit-chain verifier |
| `docs/source-checklists/` | The original `.xls` files, for provenance |

## Commands

```bash
npm run dev          # local dev server
npm run verify       # typecheck + lint + test, same as CI
npm run build
npm run db:generate  # create a migration from schema changes
npm run db:migrate   # apply migrations (uses DIRECT_DATABASE_URL)
```
